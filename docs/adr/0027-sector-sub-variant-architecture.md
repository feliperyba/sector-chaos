# Sector Sub-variant Architecture, Purposeful Geography, and Type-Coded Biomes

The seed map's POC generators produced repetitive, low-variety sectors (GridArena ignored RNG entirely so every instance was byte-identical; Maze was 4-fold mirror-symmetric; ResourceRich was 5–8 lone "stub" walls; OpenArena varied only which 2–3 fixed corner clusters appeared) and the 4×4 read as 16 sealed boxes. We keep the fixed 4×4 / 20×20 grid, the 3-wide central corridors, and the siege / 4-spawns-per-sector / loot-ring / minimap coupling — and instead **deepen the interiors**. Each **Sector Type** now carries one fixed **Gameplay Purpose** plus one shared balance budget, and is realized by one of **4 procedural Skeletons (sub-variants)** chosen per sector instance from the seed, with the same sub-variant never placed in two orthogonally-adjacent sectors (4 per type, **16 skeletons total**). **GridArena gains a persistent indestructible pillar skeleton with breakable fill** (deviating from GDD §5.2.1's destructible pillars) so it keeps its close-combat identity all match. **Maze becomes asymmetric, mixed-width, looped, with breakable `wall_secret` shortcuts** (deviating from GDD §5.2.3's mirrored width-1 maze). **Type placement becomes center-hot** — the center 4 sectors trend ResourceRich + GridArena (the loot brawl / siege endgame), the outer ring trends OpenArena + Maze (landing, skirmish, rotation) — replacing the random weighted pick + corner-pinned minimum-types + 2-consecutive cap. **Visuals become type-coded Biomes** (a signature floor palette + decorative-tile set per type, signalling purpose at a glance) plus per-instance **Decorative Accents** (cosmetic, non-colliding).

## Considered Options

- **Hand-authored room templates stitched together** — rejected (prior locked decision): generation stays fully procedural; templates fork content authoring and fight seed determinism.
- **Erodible GridArena lattice (current GDD §5.2.1)** — rejected: a fully-flattened grid loses its close-combat purpose mid-match, so a GridArena can "become" an OpenArena and the type stops meaning anything.
- **Keep the mirror-symmetric width-1 Maze** — rejected: reads artificial/repetitive, width-1 everywhere is unfair for melee, and dense 1-wide corridors are the worst case for 63-bot LOS/pathfinding cost (ADR 0024).
- **Region biomes decoupled from type** — rejected: slower to read in a competitive BR; type-coded colour tells the player which fight they're walking into.
- **Random type placement** — rejected: no intentional risk geography; the "center matters" signal would rest entirely on the loot ring.

## Consequences

- GDD §5.2.1–5.2.4 and §5.3 are amended; this ADR is the recorded *why* for the deviations.
- Sub-variant selection is **centralized in `MapGenerator`** (passed via `SectorConfig.subVariant`) so adjacency-dedup and center-hot placement live in one place; the four sector generators become pure skeleton builders.
- `MapValidator` gains quality gates feeding the **existing 10-retry loop** — new skeletons that starve spawns or loot are retried, not shipped. As shipped: minimum interior open-ratio `MIN_OPEN_RATIO = 0.35`, ≥64 spawns with per-sector spawn feasibility (`MIN_SPAWNS_PER_SECTOR = 4` plus the map-wide overflow rule), per-sector loot feasibility (chest + barrel + minimum-loot budget), and an isolated-stub-wall cap `MAX_LONE_WALLS = 60`.
- Floor theme is now **type-coded** (Biome), reversing CONTEXT.md's former "independent of sector type" rule; the floor underlay stays sterile-clean, with variety moving to the Decorative Accent overlay. As shipped this is a strict 1:1 assignment — exactly one distinct signature floor sprite per type (GridArena=`tiles_center`, OpenArena=`grass`, Maze=`tiles`, ResourceRich=`tile`), with `wood` reserved for edge framing — plus a per-type, collider-free EMPTY-type Decorative Accent set. Decorative Accents are composited as a **dedicated overlay layer**, not a floor replacement: the Seed Path emits four stacked layers in the order **floor → decoration → walls → interactive** (`SeedMapAdapter`), painting accents only on EMPTY interior cells on top of the opaque base floor, so transparent decals never punch holes in the underlay.
- Walls render with **collider-compatible sprite variety pools** (a deterministic per-cell pick within a pool whose colliders all match the cell's wall role), not a single map-wide material. **Free-standing obstacles** — a wall cell with ≤1 wall-like cardinal neighbour (isolated pillar or 1-connection stub) — render as **full-tile OBJECT art** (`coffin`/`crate_small` for indestructible, `crate`/`tree`/`planks` for destructible) carrying full-tile colliders; connected runs/corners/borders keep the autotiled bar/corner art. This logic lives in `wallSpriteResolver.ts` (called from `SeedMapAdapter.buildWallLayer`); the classifier/orientation detector and the faithful-enriched collision mechanism (ADR 0023) are unchanged. See ADR 0023's "Map Cohesion Revamp" update for the scoped collision consequence.
- Elevation stays deferred (always `null`); weather stays cosmetic. Unchanged by this work: the fixed 4×4 / 20×20 grid, the border ring + 3-wide centered corridor model, the siege / 4-spawns-per-sector / loot-ring / minimap coupling, the wall autotiler's orientation/classification, and the faithful-enriched collision *mechanism* (ADR 0023). (The wall autotiler's *sprite selection* did evolve in the Map Cohesion Revamp — variety pools + full-tile object art for free-standing walls — see the Consequences entries above.) Corridor-length variation was considered and is explicitly deferred.
- A **seed-gallery preview harness** becomes the primary quality instrument (human variety/coherence judgment), matching the team's see-it-render verification preference; it is built first (Wave 0) so nothing large lands blind.
- Per-type balance budgets are unchanged in value (existing `CHEST_COUNT` / `CRATE_DENSITY` / barrel / trap / ground-weapon rules); crate density auto-scales because it is a fraction of EMPTY tiles.

## Revamp 2: Cohesion & Tile-Variety Enhancement

Revamp 1 (above) deepened sector *interiors* (sub-variant skeletons, type-coded biomes). Revamp 2 is a visual-cohesion + tile-variety pass that improves how those interiors *read* as deliberate places rather than generator noise. It touches only the floor-decoration surface and connector openings; the skeleton types, balance budgets, collision, siege/loot-ring/minimap, and the autotiler's faithful-enriched mechanism are unchanged. It was built in five slices (R0–R4).

### R0 — Sprite-faithful gallery

A new server-side gallery (`packages/server/scripts/sprite-gallery.ts`) runs the **full `SeedMapAdapter` pipeline** and renders **sprite-path-colored cells** (49+ distinct colours keyed by the resolved sprite `imagePath`) instead of the original gallery's `TileType`-only colouring. The original gallery (`packages/shared` map-gallery) painted by structural TileType, so two cells with identical types but completely different art (a `crate_small` pillar vs a `coffin` pillar) looked identical — structural blindness that hid exactly the variety Revamp 1 added. The sprite-faithful gallery makes every distinct rendered sprite visually distinct. **Both galleries are kept**: the shared TileType gallery for structural-layout inspection, the server sprite-path gallery for art-fidelity inspection.

### R1 — Corridor floor theming + plaza accents

The 3-wide central corridors previously inherited the `wood` edge floor, reading as framing rather than connecting paths. Corridor cells (`mapData.corridorTiles`) now get a **themed corridor floor**: `path` for horizontal corridors (cells on left/right sector seams) and `track` for vertical corridors (cells on top/bottom seams), so corridors read as deliberate connecting paths distinct from both sector interiors and `wood` borders (`FloorSpriteSelector.ts`, pure positional — no RNG). Each sector's **central 4×4 region** (local rows/cols 8–11) additionally receives a **plaza accent** — a distinct solid floor sprite per type that differs from the biome floor, creating a visual focal point in every sector.

### R2 — Seam thinning + varied openings

Internal sector seams were a doubled 2-thick wall line with one fixed central 3-wide gap per edge. `SectorConnector` now **thins the seam to 1-thick** (one sector's border is cleared to EMPTY, the adjacent sector's border is kept as the single seam wall) and carves **1–3 varied 3-wide openings per edge** instead of one fixed central gap (weighted: ~50% one opening, ~35% two, ~15% three). Opening selection consumes an **isolated RNG** derived from `seed ^ 0xc0ffee` so the main pipeline RNG — and therefore downstream entity/loot/spawn placement — stays byte-identical to pre-R2 output. The **outer map perimeter is unchanged**; **corner cells are always preserved** so structural corners stay intact. The 3-wide opening width and the connectivity-repair BFS (`ensureInteriorConnectivity`) are unchanged.

### R3 — Interior cover cohesion

Single-tile scatter cover rendered as isolated objects. Two sub-variants now place **breakable cover as 2-tile runs** (a horizontal or vertical pair) so the art reads as a connected bar/corner rather than a lone crate: GridArena **Ring Fortress** and OpenArena **Scatter Cover**. Cover density budgets are unchanged; only the *clustering* of the placed tiles differs.

### R4 — Decoration clustering + expanded palette

Decorative accents previously landed via uniform random scatter over EMPTY interior cells, reading as noise. They now land **preferentially (~70%) on structure-adjacent EMPTY cells** — cells with ≥1 non-EMPTY cardinal neighbour — leaving ~30% as free scatter, so set dressing reads as hugging walls/pillars/cover naturally (`CLUSTER_PREFERRED_RATIO = 7` in `FloorSpriteSelector.paintAccentPass`). The decoration palette **expanded** with new atmospheric tiles: `stairs_down` and `water` added to the Maze decoration set, `stairs_down_detail` added to the OpenArena set. All new decoration tiles remain collider-free EMPTY-type overlays (no gameplay effect).
